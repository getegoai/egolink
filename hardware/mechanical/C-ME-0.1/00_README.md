# Ego Link C线｜核心舱结构与建模启动包
版本：**C-ME-0.1**　日期：**2026-09-09**　状态：**建模设计输入／可迭代草案，非生产冻结**

## 本包交付
- `01_CODEX_STRUCTURE_TASKBOOK.md`：Codex执行顺序、三软件协作、交付与验收。
- `02_CORE_MECHANICAL_CONCEPT.md`：核心舱结构草案、两档体积起点、内部堆叠、声学/光学/RF/电源约束。
- `03_EGOLINK_MEMORY_CURRENT.md`：可单独上传到下一次聊天或放入仓库的当前记忆基线。
- `04_DECISION_LOG.md`：决策来历、被替代的安排、未决事项和迭代记录规则。
- `05_CUSTOM_SHELL_CONTRACT.md`：用户可定制外壳与承力载体的边界，接口尚未发布。
- `07_CODEX_START.md`：可直接交给Codex的启动指令。
- `06_SOURCES.md`：用户/历史资料/外部官方资料分开记录。
- `params/core_parameters.json`：机器可读的工程假设、真实器件缺项和建模参数。
- `scripts/`：输入校验、FreeCAD外包络宏、Blender导入脚本、Windows安装探测脚本。
- `cad/`：两档**实心外包络**STEP/STL，可打开或制作尺寸手感样块；无内部装配结构。
- `reports/`：本环境实际完成的校验结果；本机三软件的执行结果由Codex后续补入。
- `references/`：用户提供的三张设计参考图，未改动，不是工程尺寸图或认证证据。

## 如何用
把本目录放到项目一个新版本目录下，推荐 `hardware/mechanical/C-ME-0.1/`；现有仓库有固定约定时沿用它。让Codex从任务书开始执行。不要覆盖历史A0/A1、R03、C0.1或C1.0-review文件。

本轮先完成“工具探测 → 参数和来源核验 → 双包络打开 → 第一轮器件占位/冲突图 → 初步外壳结构”，不先做复杂渲染。缺供应商数据时允许做明确标注的占位体，不允许用其宣称装配已通过。

## 本包的真实边界
本包已实际生成STEP/STL外包络及校验结果；这些是尺寸模型，不是可装电子件的外壳。未生成或声称存在最终`.FCStd`、`.blend`、`.kicad_pcb`、PCB网络表、完整密封结构、模具或制造发布文件。

FreeCAD/Blender/PowerShell脚本在此环境只做相应可执行部分或静态校验；没有调用用户电脑上的软件。用户已安装Blender、FreeCAD、KiCad，准确版本和路径待Codex本地探测。不要求再装软件或先装插件。

本文档记忆已写入实际文件；不等于已写入产品仓库或跨会话自动长期记忆服务。
