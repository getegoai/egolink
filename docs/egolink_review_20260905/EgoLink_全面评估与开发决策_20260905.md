# EgoLink 全面评估与开发主导决策

**审查日期：2026-09-05｜运行证据截至：2026-09-04｜范围：文档证据审查、架构决策、执行重排、核心文件修订候选**

## 一、结论

EgoLink 已经积累了有价值的通信、传感器、音频、状态管理、协议和测试资产。
当前主要瓶颈是把这些资产变成同一个可运行系统，并在真实使用条件下证明它。
我的判断是：**保留产品核心方向，立即改变开发推进方式；复用已有代码，以真实端到端结果重新组织任务。**

最新首发目标“Reliable Location + Ego Call + physical SOS”足够明确，继续保持。
本轮不增加摄像头、多模态理解、宠物专用能力或大模型依赖；也不为了显得进展快而把三项产品 Gate 改为通过。
下一阶段的主导目标是：**让真实设备的位置可靠地显示出来，让物理求助确实到达指定的人，让双方真实听见对方。**[S3][S5]

本轮查看了五份最新上传核心文件和项目旧主上下文，并对部分技术路线核对了原厂资料。
没有读取实际 Git 工作树、源代码、原始测试日志或当前 VPS；没有独立重跑 1614 项测试，没有烧录、部署或进行硬件实验。
因此，下面严格区分“文件记录的事实”“根据记录作出的判断”和“本轮决定的目标设计”。
仓库路径、协议符号、函数调用关系和实施差异，应由实际工作台的 Codex 在首次落库时核实。

## 三、最需要改变的是进度单位

8月23日记录全仓库 929 项测试通过；9月4日为 1614 项通过、12 项跳过。
期间确有音频端点的硬件进展，不能说“完全没有做实机”。但最新定位和通话候选仍未运行，三个产品闭环没有形成新的 Gate 证据。
这些测试可能消除了真实缺陷；测试数本身无法说明离可用产品还有多远。[S2][S4]

我将主进度单位改成四项：用户实际多获得了什么能力；它在哪个真实条件下运行；还会怎样失败；下一次验证将消除哪一个最大不确定性。
构建成功、接口完成、重放通过和源代码检查继续报告，放在对应证据层，不再代替交付结果。

**任务组织随之调整。** 一个任务可以跨固件、服务端和 Guardian，但必须围绕一个用户结果。
实现仍可拆成小提交；拆分不再把每个 adapter/owner/runner 都变成独立的“产品进度”。
新增准备性抽象必须有一个即将执行的具体消费者。共享代码交给集成负责人，两个独立构建者最多并行修改不重叠路径。

## 五、四个必须优先核查的架构问题

### 5.1 LOC-021T0/T1 的全局排序和 WAL 是否超出了当前闭环需要

现有任务树将持久化 occurrence-ordered ingress WAL、lane watermarks、K checkpoint、outbox tombstone 和 no-output replay 放在下一产品集成之前。
同时，它已经允许独立 S modem-only smoke 不等待 T0/T1；这一点应保留和利用，不能把现有路线描述为绝对禁止实机。[S5]

这些机制各有合理用途，但需要回答：哪些输入必须跨掉电恢复？哪些顺序决定了不可重复的外部动作？当前实时决策究竟需要等待多久？
异步源的真实事件时间、设备实际处理顺序、服务端接收顺序应分别记录。
同一时钟域可按事件时间比较；不同时钟域无法无条件比较时，应保留时间不确定性。
实时处理采用有界输入、计时器和迟到策略，不等待所有传感器证明“再无更早输入”。

我的默认目标设计是：**本地有界状态处理 + 小型恢复检查点 + 关键待投递事件 + 后端丰富重放**。
历史分析可以重新排序；它应保留当时真正作出的在线决定，不能把事后推断冒充在线表现。
若现有 T0 实现已是达成这些不变量的最小方案，就直接复用；不为“简化”再重写一次。

本轮解除的是有限单源/单次启动实验对完整通用 WAL 的依赖。
原并发 T1 在旧承诺下仍需原保证；需要降级范围时使用独立命名 profile 并公开缺失保证。

### 5.2 本地位置状态不应被“上传记录写不进去”卡死

LOC-021J 的描述是：要求的 state envelope 未持久入队前，不提交 staged state。[S2]
这能保护状态与输出的一致性；同时提出一个需要用代码和测试回答的问题：队列满或 flash 失败时，本地位置、位置老化和 SOS 策略是否继续工作？
本轮没有源码，不能断言它已经有 bug。

目标设计区分四种状态：最新本地观测/推断；最后持久检查点；等待上传的记录；服务端确认的状态。
本地状态可以继续在 RAM 中更新，但必须标记持久化失败，并保留最后可恢复版本。
对承诺持久交付的事件仍保持 write-before-send、稳定身份、匹配 ACK 和受控重试。
普通周期状态可以按明确规则合并；关键事件不能因普通状态拥塞被静默挤出。

### 5.3 SOS 存储失败时要有明确的求助降级路径

现有文档把 journal/enqueue 排在本地反馈之前。[S4]
应拆开“输入已识别”“已保存”“已到服务器”“对方设备已提示”“对方本人已确认”五种事实。

长按满足条件后，先给出含义准确的本地输入反馈，同时尽快尝试关键事件持久化。
正常路径保持持久优先；存储异常时显示存储失败，尽可能沿仍然可信的身份、授权和安全通道发送临时求助并尝试联系。
该降级事件不声称可跨重启恢复，可靠性结果仍为失败。
如果身份或密钥也不可用，就只能给出明确本地失败状态，不能为了发送消息而绕过认证或 TLS。

历史 Replay 不产生新外部动作；服务恢复却必须继续处理未投递的有效 SOS。
两者不能混用。已结束/过期通话不能因重启重新拨起，未完成报警也不能因“no-output replay”被永久搁置。

### 5.4 通话 PoC 要尽早证明可迁移到嵌入式路径

当前 CALL 仍欠真实连接、实际 TLS/SIM 路由、结果遥测及运行内存；此前 RNDIS 只证明枚举，历史绑定地址的 ping/curl 超时。
这说明网络接口存在不等于媒体链路成立。[S2][S4]

我保留现有 PC 桥做诊断夹具，并将“真实声音双向传递”放到最前。
同时做一个短而具体的嵌入式承载验证，不等最终 PCB 才发现不能迁移。
具体 modem 的 AT、GNSS 和数据承载共存必须由同一个 owner 管理，核实 UART、流控、CMUX/独立通道和断链恢复。
不因官方库支持 SIM7600 就假定 SIM7670G 已经兼容。

原厂 `esp-webrtc-solution` 已提供 PeerConnection、采集和播放组件及双向音频示例，可作为复用候选。[W1][W2]
`esp_modem` 提供 PPPoS、命令/数据模式及扩展接口，同时记录了 UART/TLS 和部分 CMUX 兼容问题；使用前应锁定版本和准确模组验证。[W3]

**优先复用成熟媒体栈；协议、权限、安全状态与产品交互由 EgoLink 自己掌握。**
这不是立即替换现有 CALL 的命令。先比较准确板卡/codec、依赖许可证、IDF、内存、移植工作和实际运行结果，再决定最短可行路线。

USB Serial/JTAG 是固定功能串口/JTAG，原厂记录其控制台缓冲在一定条件下可能出现一次约 50 ms 等待和睡眠影响。
这给共享控制台/媒体通道的调度提出验证要求，不能据此断言当前自定义驱动必然产生 50 ms 延迟。[W4]
浏览器 WebRTC 还涉及信令、媒体与安全协议，单个 TLS 流的成功不是完整通话验收。[W6]

## 六、可靠定位和 AI 的下一步

### 6.1 把“可显示的状态”与“可用的位置”分开

保留最后可信位置是正确方向，但它必须同时显示时间和不确定性。
当设备移动、时间增长或证据矛盾时，不能只维持地图上一个看似精确的新鲜点。
冷启动且没有任何绝对位置锚点时，Unknown 是正确结果；界面仍可以给出最后历史证据、连接状态和正在采取的定位动作。

在信息完全相同、且不存在可区分地理锚点的两个地点，任何算法都无法凭空判定是哪一个。
因此，AI 的价值应通过可靠性估计、运动状态、已学习地点关联、传感器调度和不确定性校准来证明，不能承诺无条件恢复精确坐标。

还应核查 LOC-021L 对“正 HDOP 才接受 fix candidate”的条件。
建议分别保留接收机 valid fix、质量字段完整性和算法可信等级；缺失 HDOP 可意味着质量信息不足，不能自动等同 no-fix。
这一点需对准确接收机输出和代码映射做实证审查。[S4]

### 6.2 用一次真实场景比较推动算法，而非扩建训练平台

最小对照包括：GNSS-only、last-trusted + age、加 motion/source-state 的规则基线，以及候选可靠性估计器。
按路线/会话划分验证集合，不把同一连续轨迹的相邻窗口随机散进训练和测试。
初期使用自然携带和明确记录的参考方法；手机定位可以作为带误差的工程参考，不能冒充准确地面真值。
保留 no-fix、未尝试、超时、断网上传缺口和时间对齐不确定性。

指标至少同时看：时间加权可用位置比例、位置年龄/长时间失效、参考可用时的误差分布、估计范围覆盖率、请求到结果延迟和能耗。
上传成功率与位置有效性分开；准确率与覆盖率一起看，防止通过丢弃困难样本制造漂亮数字。
模型先离线比较，再影子运行，不阻塞首发确定性安全路径。

## 七、硬件、功耗、Guardian 和商业边界

### 7.1 硬件先形成有代表性的工程载体

保留现有板卡和已验证端点，先做固定安装、明确天线位置、独立供电、可重复携带的工程组合。
必要时采用载板或工程互连，尽早排除电气和资源冲突；不要求为第一次有效外场先完成最终小型化 PCB。
当前 AMOLED 继续承担状态显示和交互验证，不由此推导产品必须采用该屏幕。

先验证一个主用场景：需要亲友远程联系和看护的人身安全随身终端。
儿童、老人可以保留为产品对象；首轮携带与可用性研究应选择一个人群和一种佩戴方式，成年人参加受控工程测试。
宠物及多种壳体作为后续适配，避免同一轮同时冻结腕表、挂件、项圈三种约束。
最终有无屏幕、尺寸和电池容量要结合现行产品文件与人因结果，不从过时主上下文直接选定。

### 7.2 功耗从现在测，续航承诺单独证明

目前缺少新候选的完整运行功耗和动态内存证据，不能根据芯片或编译体积推出七天续航。[S2]
把待机/注册、GNSS 捕获、一次上传、弱网重试、通话、SOS、充电和峰值供电分开测量。
以电池端电流积分或统一能量口径形成典型日/弱网日预算，明确实际电池容量、温度、转换损耗和保留容量。

仅作算术示例：假设电池标称 800 mAh、可用容量按 80% 计，七天平均电流上限约为
`800 × 0.8 / (7 × 24) = 3.81 mA`。
这不是产品电池选型、当前测量或七天已达成的结论。
48 小时压力测试有价值，但它不自动验证七天目标。
运行内存应测最小剩余堆、最大可分配块、任务栈水位及分配失败，不能只看 ELF/分区余量。[W7]

### 7.3 Guardian 是关键路径的一部分

服务端入库和 HTTP ACK 只证明机器收到了数据。
要分别验证对方页面/应用前台、后台、锁屏、断网恢复时能否发现通知；手动确认与被动送达分开。
第一版本可以先用受控网页前台证明闭环，但必须标为前台实验，不把它称为随时可达的监护产品。
设备绑定、撤销、误绑定防护、丢失设备处理和呼叫授权与媒体成功同样重要。

### 7.4 上市条件不降级

22,240 字节全槽写入、实际掉电恢复、加密密钥、保留期实施、备份删除、RF/声学/结构和生产测试，依然是产品必须解决的问题。[S2][S4]
NVS 官方说明它适合较多小值并自带磨损均衡，大块数据有其他存储选择；这提供复用依据，但不替代 EgoLink 的多步事务与掉电试验。[W5]

文件未提供足够的目标售价、实时器件报价、通信/RTC 月成本、售后/退货模型和真实付费用户验证。
本轮不编造毛利、BOM 或上市日期。商业验证与工程并行，先说明谁购买、谁佩戴、谁响应、愿意为何付费，以及每月服务成本。
COMPLIANCE-010 继续交由合适的专业机构结合准确市场、功能和射频/语音路线作判断；本报告不出具法律或认证结论。

## 八、接下来的执行顺序

### 主线 A：先交付真实位置闭环

复用 LOC-021 已有组件，明确一个单源/单次启动的受控 live profile，接通具体安全传输与 Guardian。
S 的独立 modem smoke 可以先做。完整通用 T0/T1 不作为这个有限实验的全局先决条件。
代码必须有真正执行的入口、具体 driver/connector 和行为测试，不能以更多 fake adapter 作为最终交付。

这只是工程 smoke/bench 证据，不是 FIELD-020 或 P0-LOC 全部通过。

### 并行 B：真实双向声音和承载迁移

完成一个真正的两端媒体连接和可靠停止：人说话、对方听见、反向同样成立。
先做 60 秒受控双向 smoke；然后按既有 CALL-020 的重复与较长会话要求验证，保留十轮/十分钟 PoC 等原协议要求，不缩成一次演示。
Wi-Fi/本地证明音频，绑定且核实的 SIM 路由证明蜂窝承载；两者独立标识。
最终 PC-free CALL-021 仍以代表性产品硬件验收。

### 收束 C：物理 SOS、故障恢复和自然携带

物理长按、真实本地反馈、持久事件、Guardian 提醒、独立通话尝试连起来。
用存储满、写失败、无 GNSS、网络中断、ACK 丢失、重启和过期呼叫检验失败行为。
一次实验只引入受控故障，不在真实紧急求助中试验。
完成后进入独立电源工程携带和正式代表性场景；功耗/天线/Guardian 到达性从前两条线就开始采集。

## 九、Codex、Qwen 与授权模式

Codex 负责源代码路径追踪、架构取舍、任务切分、共享边界和最终集成。
Qwen 等执行模型承担输入输出明确、文件范围固定的实现、测试补充和文档归档；不同时改共享协议、owner、核心状态机和硬件权限。
一次交付只报告用户能力变化、真实运行的测试、当前最大阻塞和下一动作。
外部模型调用前确认数据外发权限，秘密、私有坐标和原始媒体不进入无授权提示上下文。

离线改代码、在现有受控环境构建和测试，不需要每个小步骤再问创始人。
真实烧录、传感器采集、SIM 费用和对人通知按一份明确实验范围授权；相同范围内不逐命令重复确认。
本轮用户授权支持路线和核心文件修改，但不等同对任何人任意录音、任意外部通知或破坏性操作的授权。

审查按影响分级：隐私/安全越界、错误身份、不可控硬件动作、已确认数据损坏等阻断相关执行；与当前实验无关的量产优化和文档完善排后。
不要通过无限细化条件让每一个真实实验都无法发生，也不要删掉关键测试制造通过。
对原仓库的 12 项跳过逐项标出原因和能力影响；缺失的 native 并发行为测试应到合适环境真正执行。[S4]
