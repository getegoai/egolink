# EgoLink 后台与日常试用平台设计方案

后台以现有开发板为真实测试设备，独立推进多机管理、持续采集、日常试用、数据回放和中期路演。新 PCB 调通后通过设备登记和板级适配接入同一平台。首版面向团队与少量受邀试用者，提供电脑管理控制台和手机试用页面。

2026 年 10 月 15 日，创始人确认首版主要使用者为“团队工程＋受邀试用”。页面、权限与首版实施范围按此定位设计。

本方案服务可靠定位、原生通话与实体 SOS 的后续验证，并为 D2 精度基线和 D5 数据改进提供可追溯数据。它是设计提案；现有产品决策、设备协议、硬件运行权限和验收状态继续有效。当前不改动固件、公共合同、线上服务或既有私人数据。

## 1 产品目标和首版范围

首版完成下面一条日常流程：登记设备并分配试用者，设备持续上传，用户查看当天状态与轨迹，补充场景备注，团队发现缺测或故障，结束后生成有证据入口的日报。这个流程在现有开发板上即可验证。

| 范围 | 首版交付 | 后续扩展 |
| --- | --- | --- |
| 设备 | 设备台账、型号和能力、身份别名、版本、在线状态 | 新 PCB 批次和更多设备配置 |
| 试用 | 少量邀请账户、设备分配、开始和结束试用、问题反馈 | 家庭成员及复杂共享关系 |
| 数据 | 轨迹、活动规则输出、电量、网络、来源质量和缺口 | 评估数据集与影子 AI |
| 控制 | 复用已支持命令及真实结果，按权限和能力开放 | 新板通过验证的通话和 SOS 能力 |
| 运营 | 故障清单、质量摘要、版本追溯、备份恢复 | 更大规模设备运维 |
| 演示 | 真实设备视图、授权历史回放、独立示例空间 | 对外展示和更多交互形式 |

首版按 3 至 5 台实际试用设计，容量先验证 10 台等效数据流。初始压测 profile 为每台每秒 1 条、平均 1 至 4 KiB 的合法合成观测，另测总计每秒 50 条持续 60 秒的突发；照片单列配额和并发测试。性能数字是拟定验收目标，部署规格和真实采样策略确认后复核。首片交付至少一台现有真实开发板的完整流程，多机容量可先用隔离的合成流验证。

## 2 并行工作和阻塞边界

| 工作线 | 可以立即推进 | 仅阻塞的后续环节 |
| --- | --- | --- |
| 后台 | 页面、管理数据、权限、回放、质量、报告和兼容测试 | 部署取证和真实持续试用需要对应运行窗口 |
| 开发板测试 | 按现有实验范围持续采集，验证恢复、定位参考点和后台体验 | 不能替新 PCB 证明音频、功耗或整机功能 |
| 新 PCB | 硬件调通、设计资料和能力记录 | 新板系统迁移与新板通话、SOS 实测 |
| 外壳 | 获取实板尺寸，设计托架、配件布局和打印壳 | 最终装配和带壳射频、声音、温升复测 |
| 最小 Base | 在用户控制的电脑运行软件终点，先验证合成 Session | 专用 Base 硬件和完整私有 AI |
| 数据评估 | 整理既有格式、标注与回放，建设质量规则 | 无授权或无真值的数据不能用于相应训练和准确率结论 |

后台首版不依赖新 PCB、完整通话、完整 SOS、端侧模型、专用 Base 硬件或完整四源数据包。某台设备能力缺失时，相关页面说明原因，其他流程继续。

## 3 页面和使用流程

### 3.1 管理控制台

主导航使用总览、设备、试用记录、数据与回放、报告、系统管理。报文、示波器、相机实验和模型实验收在设备详情或研发工具中，首页优先呈现需要处理的设备和问题。

| 页面 | 用户需要回答的问题 | 主要内容和动作 |
| --- | --- | --- |
| 总览 | 今天哪些机器在工作，哪些需要处理 | 设备总数、通信在线、数据陈旧、正在试用、待处理问题；设备表和最近事件 |
| 设备列表 | 每台机器是什么、给谁用、运行什么版本 | 别名、硬件形态、试用者、版本、最后通信、位置年龄、电量年龄、问题数；筛选和登记 |
| 设备详情 | 这台机器现在怎样，为什么 | 状态摘要、地图、来源、历史与事件、能力、版本、命令结果、受限诊断 |
| 试用记录 | 一次使用从何时开始，数据是否完整 | 场景、设备与使用者、时间、佩戴位置、关联运行、备注、反馈、结束和报告 |
| 数据与回放 | 当时观察到了什么，哪里缺失 | 同步时间游标下的轨迹、运动估计、电量、网络、缺口和备注；区间检索与标注 |
| 报告 | 这一天的结果是什么，能否比较 | 事实日报、质量摘要、定位参考评估、问题与版本比较；有权限的导出 |
| 系统管理 | 谁能访问和控制什么，服务是否正常 | 用户角色、设备绑定、凭证状态、审计、处理任务、容量、备份恢复和部署版本 |

总览采用上方摘要、中央设备表、右侧问题队列。地图进入设备详情或试用回放，避免多台设备的原始轨迹在总览中默认全部展开。桌面列表可排序筛选，手机端转换为设备卡片。

视觉上使用清晰的表格、地图和时间线，统一时间范围与单位。正常、陈旧、失败、未知分别带文字和图标，颜色只作辅助。主操作每页控制在一至两个，媒体和控制动作进入明确上下文；加载、空数据、无权限、服务失败和补传处理中都有独立页面状态。

设备详情顶部固定显示设备名称、硬件形态、数据来源、视图时间范围、最后通信和最后有效定位。下方提供“当前状态、轨迹与时间线、试用与问题、能力与版本、诊断”五组内容。诊断中的 boot、帧和哈希按需展开，试用者日常页面不展示这些实现字段。

### 3.2 手机试用页面

手机页面提供我的设备、今天、试用反馈三个入口。用户登录后只看到被分配或授权的设备。

“我的设备”显示最近位置及其时间、电量及其时间、通信状态和已验证的可用动作。“今天”显示轨迹、活动估计、缺测和场景备注。“试用反馈”记录定位不符、设备异常、携带不适等问题，并绑定相关时间段。

开始试用时只需选择设备、场景和佩戴位置；结束时填写是否充电、是否出现异常及关键备注。首次试用补充数据用途、访问范围、保留规则和媒体选择。后台开始试用仅建立记录，不隐含开启传感器、相机或向设备发命令。

### 3.3 关键交互

1. 管理员登记现有开发板并核对当前设备标识，分配给测试者。
2. 测试者在手机建立试用记录。后台绑定已接收或随后接收的数据范围，不要求设备认识新的试用 ID。
3. 用户外出时查看位置和状态；关键场景可补“进入建筑”“放入背包”“乘车”等备注。
4. 断网期间显示最后通信及旧位置年龄；恢复后补传数据回到原采集时间，页面另标补传。
5. 结束后先生成质量摘要，再生成事实日报。数据不足也有报告，并指出缺少什么。
6. 团队从问题进入具体时间片，查看原始证据和配置，形成下一轮测试或修复。

## 4 设备与数据身份模型

开发板属于正常设备资产。设备形态、数据真假、能力证据和此刻健康分别记录。

| 维度 | 字段含义 | 展示规则 |
| --- | --- | --- |
| 硬件身份 | asset_id、board_kind、board_revision、serial、模组和外设 | 开发板、自研 PCB 都有独立资产记录；缺失字段为 unknown |
| 来源 | real、mock、synthetic、unknown | 开发板真实传感器数据标为 real；混合 Session 按记录/窗口保留来源，mock 不计入真实覆盖 |
| 视图 | live、history、replay | 真实历史回放保留 real，同时显著标 history 或 replay |
| 能力 | 硬件有无、固件是否支持、证据范围、当前是否可用 | 接口存在、驱动存在、实测通过和产品验收分别记录 |
| 健康 | 通信状态和每个来源的新鲜度、错误、缺测 | 在线设备可以无 GNSS fix；离线不等于永久不支持 |

内部 asset_id 稳定不变；设备线上 device_id 通过带有效区间的别名映射关联。现有 physical node 名、线上 device_id 和旧运行 ID 作为不同标识保留，不能为了界面整齐重写历史。一个线上身份在同一有效区间只能对应一个资产，重复身份进入冲突队列。

历史和补传数据按可信 DeviceRun、身份绑定与源时间区间关联，不能按补传收到时的当前分配关系归属。缺少足够时间或运行证据时进入待关联队列，不自动授给当前持有人。

能力记录按 GNSS、蜂窝数据、IMU、电量、静态相机、原生拨出、原生呼入、双向音频、实体 SOS 等细分。每项绑定固件/配置、证据方法、日期、运行与限制。软件存在可显示“待验证”；当前设备不支持的通话按钮说明原因，不创建永远 pending 的命令。

## 5 核心数据对象

| 对象 | 关键内容 | 首片实现方式 |
| --- | --- | --- |
| 用户与访问绑定 | 角色、账户状态、授权设备、有效期和撤销 | 新管理数据，先用邀请账户，不建设开放注册 |
| 设备资产与别名 | 资产、线上身份、形态、批次、状态 | 新台账，关联现有 devices |
| 能力与部署记录 | 能力证据、固件/配置、来源版本、有效区间 | 新增管理记录；未上报信息不能由源码推定 |
| DeviceRun | 一设备、一次 boot、一个时钟域及版本信息 | 从现有观测建立映射；不能跨 boot 拼接单调时间 |
| 试用记录 TrialSession | 使用者、场景、时间范围、设备、佩戴、反馈、授权策略 | 管理层新对象，不占用设备原 session_id |
| 试用数据绑定 | TrialSession、DeviceRun、原始 source_session_id、序列/时间区间、快照边界 | 可跨重启；无法确定的数据标待关联，禁止静默猜测 |
| 原始观测与投递尝试 | 原始字节、原有唯一键和哈希、解析结果、收件/入库时间、重复与冲突 | 复用 collection、raw frame 及相关存储 |
| 状态与回放投影 | 当前值、来源/事件时间、年龄、规则版本和输入引用 | 派生索引，可从不可变输入重建 |
| 命令与结果 | 请求者、目标、期限、原有命令 ID、回执及实际效果 | 复用唯一命令队列；管理层补权限和审计 |
| 备注与问题 | 时间区间、记录者、文本、类型、证据与处理状态 | 复用已有备注，再增加问题工作流 |
| 报告与任务 | 快照、输入范围、生成器版本、状态、报告修订、错误 | 后台任务，不阻塞接入请求 |
| 数据策略与终点 | 用途、授权、访问、配额、期限、实际存储位置、终点收件状态 | 明确工程 VPS 与私有 Base 的区别 |

一个试用记录可以包含多个 DeviceRun。原始观测可被不同分析快照引用，但单次报告对同一观测只计数一次。相同来源数据被多次导出也不能成为多份独立训练样本。

试用记录的 open、closed、processing、ready、failed 表示工作流程；质量的 ok、warning、insufficient 表示数据适用性。结束试用不等于数据合格，数据不足不妨碍结束记录和提交反馈。

现有标准 Field Session 用于可封存的数据包，保留其原 session_id 和资格规则。日常试用对象可引用或导出该包；只有符合对应合同才生成标准 Field Session。不能让 A-R0 四源加人工事件的资格要求阻挡普通后台试用。

## 6 时间与状态展示规则

同时保留 source_event_time、device monotonic time/clock domain、server_received_at 和 server_persisted_at。前者描述发生时间，后两者描述传输与存储。缺少可信 UTC 时显示相对时间和不确定性。

当前状态按每个来源独立更新；迟到记录进入历史，不覆盖更新的当前值。已结束设备运行的补传不能把旧 boot 重新变成当前运行。未来时间、未知映射或不可比较时钟的记录可以保存，但不能仅按其 UTC 或 boot 数值抢占当前值；来源顺序只在已确认的 DeviceRun 和时钟域内比较。允许同一时段多个来源并列，不强行制造跨时钟的精确总顺序。

通信状态依据真实设备请求和配置的预期上报周期 T 判断。建议初始阈值为 max(3T, 60 秒) 后显示通信延迟、max(10T, 300 秒) 后显示失联；未知 T 时使用显式工程配置并标明。浏览器刷新、回放和服务器任务不能刷新设备最后通信时间。

各传感器使用自己的采样/上传策略判断新鲜度，周期变化按有效配置生效。定位卡始终显示坐标来源、位置年龄、不确定性与 no_fix/Unknown；电量卡同样显示观测时间。实际状态例子是“设备在线，最近定位为 18 分钟前，当前无有效 fix”，而不是一个绿色正常标记。

命令、实际效果和人工结果分栏显示：

- 请求已登记、待设备轮询、设备收到、设备报告执行结果，按现有回执映射。
- 照片拍摄、保存、上传、预览是独立事实；AT 发送、振铃、接通、双向声音验证也是不同事实。
- 取消请求不等于已经取消；过期后不自动重放拨号或拍摄。重试遵守现有命令 ID、期限和幂等规则。
- SOS 的本地识别、持久化、平台收到、通知终端和人工确认分别显示；回放不触发任何外部动作。

这些是管理读模型，不能在本方案中替换既有线协议枚举或严格 ACK。

## 7 服务结构和技术路径

第一轮保留仓库已有 Python 服务、SQLite 及 Web 技术，重做信息架构与业务流程，复用接入和存储。前端按页面和领域拆成独立模块；不把引入新框架、迁数据库或引入分布式基础设施作为首版前提。

```text
现有开发板 ──既有 HTTPS 与原始帧──> 兼容接入与持久证据
新 PCB 设备 ──适配后同一入口─────>         │
                                        │ 增量读取与水位
                                        v
                                  投影与报告任务
                                        │
                用户与权限 ──> 管理 API 与试用 API
                                        │
                              管理控制台和手机页面

兼容接入 ──既有唯一命令队列──> 设备轮询与严格 ACK
私有终点适配 ──> 用户控制的 Base 保存与回放
```

逻辑模块包括设备台账、访问控制、试用与问题、状态/时间线、质量/报告、命令门禁和审计。部署先为一套管理服务加一个有界后台任务进程。接入仍由现有服务承担，投影模块不得写入旧业务表或直接操控设备。

首片只投影已确认追加且不可变的 collection 观测和投递尝试，按各表原记录 ID 与水位读取，事务写入新派生表与水位；任务中断后幂等续跑。raw frame 的解析结果、commands 和照片状态会原地更新，不能只按新增 ID 消费。它们分别使用变更版本/游标或有界未终结对象重查；尚无可靠变更入口时可查询现有服务，不作为 A 的完成前置。冻结报告绑定实际输入内容哈希和版本，不能仅把 max ID 当成所有表的完整快照。

原收件和入库时间来自源记录，投影时间另存。投影落后时界面显示延迟，不修改设备 ACK 或原始记录。

管理台账和读模型使用独立数据库文件，限制一次读取条数和重算资源，保护采集写入。SQLite 并发、锁等待和可用磁盘容量要做目标负载实测。后续是否更换数据库，以锁等待、查询和恢复成本为依据，不预先增加新服务依赖。

首次页面更新使用约 10 秒轮询，服务侧增量投影目标 P95 不超过 3 秒；页面最终可见目标 P95 不超过 15 秒。分别记录设备上报延迟、接入入库延迟、投影延迟和前端刷新延迟，避免把它们合成一个无法定位的问题。

## 8 API 与现有系统兼容

现有设备 origin、路径、原始字节、poll、命令 ID 和 ACK 接受条件保持兼容。新浏览器管理接口可放在单独的 /console/api/v1 命名空间；以下为设计中的接口族，实施时才冻结合同。

| 接口族 | 主要职责 |
| --- | --- |
| auth 与 me | 邀请、登录、退出、会话、自己的角色和设备授权 |
| overview | 设备摘要、试用汇总、需要处理的问题 |
| devices | 台账、别名、能力、部署记录、当前状态 |
| trial-sessions | 创建/结束试用、运行关联、数据绑定与质量 |
| timeline | 分页轨迹、来源时间线、区间查询与问题证据 |
| annotations 与 issues | 场景备注、问题创建、处理与复核 |
| commands | 在服务端检查权限、能力和期限后调用现有命令服务 |
| reports 与 jobs | 提交生成任务、查询状态、报告修订与授权导出 |
| operations | 健康、投影水位、存储、版本、备份和审计 |

管理接口以不透明 cursor 分页，默认不返回原始媒体或全部报文。重任务返回 job_id；重复创建试用、报告和命令通过幂等键防止浏览器重复提交。

迁移分四步：

1. 离线使用明确标为 synthetic 的固定输入，验证新领域层和页面。
2. 对授权的现有开发板数据建立只读投影，核对唯一记录数、时间与快照；不复制未获授权的数据范围。
3. 新增账户、试用、备注和报告；命令仍只有现有队列一个写入口。限制普通用户访问旧工程页与旧管理接口，不能只隐藏链接。
4. 一致性和权限验收后，再分片替换旧页面或服务内部实现。保留入口切换和应用版本回退；发生不兼容数据库变更时先验证恢复方案。

旧设备的严格 ACK 仍表示原有 VPS 持久化边界。管理 API 的成功、投影完成或 Base 收到均不能替它产生正 ACK。过渡期不让旧服务和新服务双写同一业务表，不建立第二个独立命令队列。

## 9 账户与权限

首版采用团队邀请账户和设备访问绑定。角色是系统管理员、工程人员、试用者、只读演示者；角色决定动作种类，授权绑定 asset_id、TrialSession/有效时间范围及动作，媒体访问与导出另有权限。设备重新分配后，新试用者不继承前任轨迹、报告、备注、媒体和导出；历史授权检查贯穿查询与派生结果。

| 动作 | 管理员 | 工程人员 | 试用者 | 演示者 |
| --- | --- | --- | --- | --- |
| 查看被授权设备 | 是 | 是 | 是 | 仅演示范围 |
| 登记/分配设备、管理账户 | 是 | 按授权 | 否 | 否 |
| 建立试用、备注和反馈 | 是 | 是 | 仅自己被分配设备 | 否 |
| 读取原始报文/媒体、导出 | 按数据权限 | 按数据权限 | 默认关闭 | 默认关闭 |
| 发送设备命令 | 按能力和实验范围 | 按能力和实验范围 | 仅明确开放动作 | 否 |
| 修改凭证和数据策略 | 是 | 否 | 否 | 否 |

浏览器通过服务端登录会话访问管理接口，使用 Secure、HttpOnly、SameSite cookie，修改请求校验 CSRF 和来源。设备接入凭证不发给浏览器，不继续依赖把全局 Hub token 粘贴到 localStorage 的登录方式。用户密码使用维护中的密码哈希实现，不自制密码算法；库版本在实施选型时核验。

现有开发板可继续使用当前凭证，但登记为 legacy_shared，限制到明确设备 allowlist 和必要接入、轮询、ACK 路径。共享凭证不能强证明设备身份，页面和审计保留这个边界。新设备逐台配置独立凭证；轮换需要设备配置配合，不能作为只读后台首片的阻塞。

凭证撤销后禁止新请求，登录会话和设备分配撤销分别生效。授权检查在 API、媒体内容、导出和命令服务端实施；猜测另一台设备 ID 不能访问它。审计记录请求者、设备、动作、时间、结果和对象 ID，避免记录 token、完整私人轨迹或原始媒体。

管理 API 通过固定的服务端适配访问旧接口，不把 Hub token 交给浏览器，也不提供可由客户端指定任意上游路径的通用转发。旧工程页面及管理接口由工程访问策略保护；普通用户即使知道旧 URL 也不能绕过新权限。

## 10 存储位置与运行保障

当前工程阶段继续使用已授权 VPS 采集路径，界面明确显示“工程采集存储”。目标架构由云端负责接入、中继和信令，用户私有 Base 保存历史。两种运行方式共享状态和报告模型，但实际存储位置与保护状态必须来自部署配置和可验证结果。

最小 Base 可以先在用户控制的电脑运行，接收授权或合成 Session 并验证私有持久化、回放、导出与删除。它与后台并行，专用硬件不作前置。现有 VPS 数据不因新后台上线自动迁移或删除。

每类数据配置用途、访问、配额、保留期限和实际清理状态，按原有授权与更严格的有效策略执行，不通过本方案扩大采集或保留范围。媒体默认关闭；工程拍照继续使用具名授权和现有配额/期限。采集、训练、对外演示是不同授权。

派生索引、报告、导出缓存、任务临时文件与备份继承源数据的用途、访问及最迟期限。冻结快照不延长授权；到期或撤销后按策略关闭访问并处置副本，后续查询返回 expired/unavailable 或明确缺失原因。

中继接收与 Base 耐久接收分开记账。切换终点前需审核 ACK 和故障恢复合同；唯一待交付副本不因 TTL 静默删除。容量耗尽时拒绝新增、保留负 ACK/失败状态并暴露原因，不把未耐久数据记为成功；恢复或授权处置单独执行。

后续获授权的数据删除覆盖原始记录、派生投影、报告、服务器导出和任务输入，并以有界生命周期标记阻止重算恢复已删除内容。备份按原数据用途和期限处理；媒体不进入会延长其授权期限的默认长期备份。隔离恢复后先重新应用有效删除标记再开放查询，不能承诺撤回用户已下载的文件。交付受阻的数据按明确最长处理窗口告警并进入恢复或授权处置，不能以唯一副本保护无限保留。

| 运行项 | 首版设计要求 |
| --- | --- |
| 环境 | 本地开发与测试环境使用合成数据；现有采集服务和新控制台可独立发布与回退 |
| 进程 | 既有接入服务、管理服务、单一有界任务 worker；重任务不占接入请求线程 |
| 健康 | 接入错误、入库耗时、投影水位、任务失败、磁盘/媒体配额、最后成功备份 |
| 数据库 | 复用原始证据账本，新增管理/投影库；一致性读取和增量水位测试 |
| 备份 | 使用一致性数据库备份，逐类声明数据/媒体可恢复范围；恢复已备份内容后读取实际字节并复核数量与哈希；未备份媒体明确不可恢复 |
| 恢复 | 拟定 RPO 24 小时、RTO 2 小时的工程目标；实测后报告实际结果，投影库可重建 |
| 版本 | UI、API、worker、schema migration 各自绑定 commit/工件摘要；设备版本单列 |
| 报警 | 先进入控制台问题队列；外部推送、短信或真实联系人通知另按授权接入 |

[现有运维记录](../operations/VPS_RUNBOOK.md)中的同盘备份不能证明整盘故障可恢复，[备份脚本](../../scripts/ops/egolink_backup.sh)也明确不包含 JPEG。方案落地时分别验证进程故障、误操作和存储介质损坏；需要介质故障恢复的内容保存到独立受控介质，且遵守相同数据授权。恢复清单存在不能替代内容可读。

容量按“设备数 × 实际记录率 × 平均字节 × 保留时长”加索引、备份和媒体预算测算。高频 IMU 以窗口/分片传输，不把每个轴样本变成一次 HTTP 请求；前端按时间范围降采样查询，原始数据保留其采样率和完整性。

## 11 质量 日报与 AI 演进

首版质量摘要给出分项和原因，不使用一个总健康分掩盖缺测。

| 指标 | 计算与展示 |
| --- | --- |
| 数据覆盖 | 各来源有效窗口的时间并集、最长缺口；策略已知时才计算实际/应采样分母 |
| 通信与恢复 | 最后设备请求、收件覆盖、补传年龄、恢复时长；无法区分原因时不归因为断网 |
| 完整性 | 唯一观测、重复投递、冲突、解析错误、已报告丢失；未收到的数据不可假定零丢失 |
| GNSS | 有效尝试和 fix 比例、no_fix 时段、来源时间；分母不明确时只显示计数 |
| 定位误差 | 仅与独立参考点/轨迹匹配计算 median/P90；HDOP 和轨迹长度不能替代误差 |
| TTFF | 有可信定位尝试开始/结束时才计算；无开始证据显示不可测 |
| IMU | 采样率、间隔、样本数、缺口、异常值和校准身份 |
| 电量与续航 | 真实电量曲线、充电/断电证据及覆盖；无完整放电周期不推导整机续航 |

事实日报展示采集区间、有效覆盖、轨迹、规则活动估计、网络/电量事件、备注与待复核问题。活动时长只累计有效窗口的并集，不跨缺口插值成静止或持续运动。缺少告警记录不能生成“全天安全”；可显示“已观察时段未记录到告警”，并附覆盖范围。

报告绑定输入快照、原始范围、生成器/规则版本、处理时间与来源。迟到数据产生新修订，不悄悄修改已导出报告；同一快照的可重复生成限于输入仍被授权保留的有效期，不能以复现为由绕过删除。任务成功只表示处理完成；no_data、partial、failed 分别可见，合成输入不进入真实日报。

后续按两片扩展：先增加区间标注、独立真值、冻结数据集与规则版本比较；再增加候选模型、独立测试集和影子回放。训练许可默认 false，人工备注/伪标签/模型预测不自动成为真值，重叠窗口按 Session 或更严格分组隔离。

现有 AI 原型的空输入合成回退、训练集回代指标、模拟日记和固定安全/OTA 文案，应在连接新后台前修正或隔离为显著示例。模型打包、离线评估、端侧运行、设备更新和实际部署分别显示状态。第一期不建设自动训练调度或自动模型发布。

## 12 中期路演视图

同一平台提供受限只读演示入口，支持三种明确模式：真实设备当前视图、授权历史回放、合成示例。每种模式在页面、截图与导出中保留模式和时间标记，演示入口不能下发设备控制。

演示可以用现有开发板呈现持续接入、轨迹、状态、电量和事实日报。通话和 SOS 展示依设备能力逐项开放，实机尚未完成的流程可用标为示例的回放说明，不计入产品实测结果。

拟定的五分钟顺序是查看几台设备及使用状态，进入一台设备，回放一次真实外出与断网补传，打开数据覆盖和日报，最后展示已验证能力及下一轮问题。用户坐标、媒体和姓名按演示授权裁剪；地图底图不可用时仍有时间线、坐标和轨迹视图。

以下是工作量估算与候选任务，不是已完成或已派发 WIP。以一名后台/前端实施者持续投入估计，基础片合计约 15 至 23 个工作日，真实试用观察期可与开发重叠。日期和资源确定后再排日历。

| D 小批试用与运维 | 3 至 5 天 | 兼容命令权限、监控、备份恢复、容量和浏览器验收、路演只读入口 | 前三片；新硬件不是软件验收条件 |

| 后续数据评估 | 独立估算 | 标注复核、冻结数据集、规则/影子模型对照 | 数据许可、质量和适用真值 |

A 中先在隔离环境交付可查看的页面；接入真实服务前落实最小工程访问隔离。B 的账户与设备隔离完成后才开放给受邀试用者。C 可在固定快照上与 B 并行实现，由同一集成人管理共享合同和合并顺序。

后端与 Web 为同一后台交付线，接入/合同只有一个集成人。Gemini 继续拥有开发板采集、恢复、路由和外场证据，硬件工程师拥有新板调通，结构线按实板尺寸推进。不得让多个实施者同时修改 collection_main、设备合同或同一命令服务。
