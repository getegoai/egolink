## Repaired behavior

- C and Python share 32 input/recovery cases. IMU needs at least two samples,
  a latest sample no older than 1 second and a 100–10,000 ms window. Auxiliary
  source freshness is 30 seconds. These are engineering parameters, not field
  calibration or accuracy evidence. Partial results score at most 0.5; all
  unknown scores 0. Future/invalid/mock/duplicate/out-of-order observations,
  clock recovery and prolonged gaps have explicit behavior.
- The canonical estimation keeps its existing field contract. DEVICE carries
  identity and actual evaluation monotonic time; UTC remains null when not
  established. API `ego_state_view.v0.1` wraps canonical `state` with provenance,
  receipt and actual storage properties. Legacy adaptation is explicit;
  invalid state retains raw durable ACK but gets no valid projection.
- Reads revalidate historical raw envelopes, order by real state source time,
  and do not let invalid rows consume the result limit. A delayed/invalid
  history can require scanning many rows; this is not a new indexed migration.
- Web renders canonical enums, unknown, mock and invalid diagnostics, calls
  these historical estimates and separates server receipt from sample time.
  Producer feature digests are not signatures or complete raw-chain verification;
  C/Python digest interoperability is not established. Encryption/TTL/private
  endpoint claims remain false where not implemented.

## Full-frame regression and remaining boundary

`quality_tests/test_ego_state_pipeline.py` compiles production `health()`,
envelope assembly, ego-state engine, sensor-policy/enum code and collection
framing. Hardware/RTOS/flash snapshots and emission sinks are offline stubs.
The successful frames are ingested through the actual store and checked against
the canonical schema. Maximum reason capacity is eight 47-character strings.

| Synthetic snapshot | Normal 12-source profile | Camera 13-source profile |
|---|---:|---:|
| Independent ego frame, largest tested | 2,064 B | 2,079 B |
| Health, short run | 2,529 B | 3,393 B |
| Health, grown counters | 2,787 B | 3,765 B |
| Health, all sources reporting loss | 4,647 B; no frame | 5,780 B; no frame |

Before splitting ego-state out, even the short camera frame was 4,261 bytes,
above the 4,000-byte capacity. The independent ego frame now remains bounded
in these scenarios and is emitted before ordinary health to preserve its
latest-DEVICE view. Projection diagnostics find the latest actual state frame.
This adds one DEVICE record/envelope per health cycle; field throughput/storage
budgets must include it. It does not change source IDs, ACK or frame capacity.

The all-source-loss health overflow predates this split and remains a named
Gemini recovery follow-up. The test intentionally demonstrates that boundary;
it does not declare complete health/loss reporting under all conditions.
See [the handoff](../current/CODEX_GEMINI_HANDOFF_20260922.md).
