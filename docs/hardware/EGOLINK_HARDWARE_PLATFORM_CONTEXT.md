## 1. 产品与硬件目标

Ego Link 首先面向中国市场开发“随身安全陪伴”产品。设备负责低功耗感知、事件检测、风险路由、本地安全反射和 4G 远程通信；复杂多模态理解、长期记忆和生成式推理由 PC Simulator / 后续 Ego Base 承担。

首发硬件工程目标：

- 正常安全守护续航不少于 48 小时；
- 轻度使用模式争取 5—7 天；
- 支持物理 SOS、4G 数据、GNSS、IMU、麦克风，以及托管 RTC Ego Call
  所需的全双工音频链路；
- 端侧确定性 Rule Policy / Safety Kernel 的资源、时延和故障恢复可测；
- 核心安全能力不依赖公网云端；
- 协议和业务逻辑可迁移到不同 MCU / AI MCU。

并行储备/成长评测包括原生 VoLTE、MotionNet、AudioGate 和按需摄像头 /
VisionGate。它们有价值但不因单项未完成而否决首发候选。

## 2. 当前实现基线

当前 P0 由两个开发节点和 PC Development Bridge 组成：

```text
wearable_node
ESP32-S3-Touch-AMOLED-2.06
├─ QMI8658六轴IMU
├─ 双麦克风
├─ 屏幕、触摸、扬声器
└─ 当前可穿戴应用主节点

connectivity_node
微雪 ESP32-S3-SIM7670G-4G 开发板
├─ 主控：ESP32-S3
├─ 测试蜂窝模组：SIM7670G
├─ Wi-Fi / BLE
├─ GNSS与摄像头能力
├─ TF卡和缓存
└─ 当前通信、定位和摄像头扩展节点

PC Development Bridge
├─ 串口自动识别和中继
├─ ContextRouter / Safety Kernel
├─ 数据记录、时间同步和事件回放
└─ 调试Dashboard
```

约束：

- AMOLED 板是当前可穿戴应用主节点；
- SIM7670G 开发板是通信扩展节点和测试模组，不代表量产模组或最终主控已经选定；
- PC 仅是开发期 Bridge 和观察工具，不是正式 Ego Base，也不能成为产品依赖；
- 不因新候选芯片出现而停止 ESP32-S3 P0、M0/M1 和真实数据采集；
- 当前开发优先积累模型规模、数据质量、功耗和通信行为的实测依据；
- 第一阶段允许 Mock 与真实驱动并存，但必须在日志、消息和记录中标明数据来源。

## 3. 产品架构原则

默认产品架构为：

```text
低功耗 MCU / AI MCU
    +
区域化 Cat.1 bis / VoLTE 蜂窝模组
    +
GNSS（模组内或独立，待实测）
    +
IMU / 麦克风 / 按需摄像头 / 交互器件
```

默认不采用“主控 + 外置 NPU”双芯片结构。MotionNet、ContextRouter 和轻量 AudioGate 不要求独立 NPU；只有真实模型和功耗测试证明外置加速器能显著改善整机指标时才重新评估。

## 4. 主控候选及当前定位

### 4.1 ESP32-S3：当前开发与成本基线

定位：

- 当前 P0 主控；
- 中国版低成本候选；
- 真实数据采集、协议、模型预算和功耗基线平台。

可承担：

- MotionNet；
- 规则版 ContextRouter；
- 小型 AudioGate；
- 极简、事件触发的 VisionGate；
- 4G/GNSS控制、数据记录和通信。

当前不做结论：ESP32-S3 是否足以成为最终量产主控，需要模型、误报率、内存和整机续航实测。

### 4.2 STM32U5A5：工程实现基线候选

定位：

- 中国版产品工程候选；
- 摄像头、音频、低功耗、安全和工具链的低风险路线；
- 用来验证“稳定做成产品”的平台成本。

优势侧重点：成熟工具链、调试与量产生态、较大 SRAM、摄像头与音频接口、国内技术支持和供应链可获得性。

注意：它不是当前固件目标，开发板到货后先移植基准模型和最小平台适配，不直接迁移全部业务代码。

### 4.3 Ambiq Apollo4 Blue Lite / Plus：超低功耗候选

定位：

- 验证 MotionNet、AudioGate 和可穿戴常开感知的能耗上限；
- 只有实测带来显著整机收益且供应、报价和 FAE 可接受时，才进入产品候选。

注意：

- Apollo4 无独立 NPU，但可运行当前微模型；
- 摄像头链路不如 STM32U5 / ESP32 顺手，视觉只作为按需弱能力；
- 开发板、样品和量产价格应分开评估；
- 不根据“某手表续航天数”直接推导 Ego Link 整机续航。

### 4.4 ESP32-P4：RISC-V与视觉增强候选

定位：

- 需要更强摄像头、多媒体、UI或较复杂 VisionGate 时评估；
- 作为 RISC-V 和国内可获得性对照平台；
- 当前不是默认主控。

原因：

- 没有独立 NPU；
- 没有片内 Wi-Fi / BLE；
- 若产品需要近场无线，通常还需 ESP32-C3/C6，增加 PCB、供电、固件和 OTA 复杂度；
- MotionNet、ContextRouter 和小型 AudioGate 可以运行，但当前需求不足以证明增加系统复杂度合理。

### 4.5 Alif Balletto B1：未来全球版候选

定位：

- 低功耗 AI MCU、BLE、安全隔离和全球化产品的长期候选；
- 不作为中国版当前开发的关键路径。

前置条件：

- 取得样品、正式阶梯报价、交期、生命周期和中国 FAE 支持；
- 确认量产硅版本与工具链；
- MotionNet、AudioGate、VisionGate 经 Ethos-U55 工具链验证；
- 整机功耗收益能够覆盖平台迁移和供应风险。

## 5. 蜂窝模组决策状态

- 现有 SIM7670G 用于 4G 数据、GNSS和开发链路测试；
- 中国版首发模组必须验证蜂窝数据、托管 RTC 数据会话、低功耗模式、
  弱网恢复、中国目标网络适配和量产认证；
- 原生 VoLTE、短信和相关数字音频接口按 G0V 储备路线独立验证。缺少
  G0V 证据会阻止把原生 VoLTE 标为可用，但不单独否决托管 RTC 首发路线；
- 全球版未来按区域建立不同 SKU，不假设一个模组覆盖全部国家和运营商；
- GNSS采用模组内还是独立芯片，由功耗、电源域、定位频率和区域复用实测决定；
- Codex不得把某个候选模组写成已冻结BOM。

## 6. 当前冻结与未冻结事项

### 已冻结

- 当前 P0 使用 ESP32-S3-Touch-AMOLED-2.06 + ESP32-S3-SIM7670G-4G 双开发板，并分别通过 USB 接入 PC Development Bridge；
- `wearable_node` 负责 IMU、音频、屏幕、触摸、扬声器和用户交互；
- `connectivity_node` 负责 4G、GNSS、摄像头和通信/缓存能力；
- 设备通过版本化 `hello` 的 `device_id` 和 `role` 识别，不硬编码 COM 口；
- 先做随身安全陪伴；
- 端侧采用专用微模型和规则混合，而非通用大模型；
- 复杂认知回到本地 PC Simulator / 后续 Ego Base；
- 固件必须保持平台可迁移；
- 续航最低目标为典型守护 48 小时。

### 未冻结

- 量产主控；
- 最终蜂窝模组；
- GNSS集成或独立；
- 双板直连接口和最终板内总线；
- 电池容量与外形；
- 是否保留摄像头；
- 是否需要片内 BLE / Wi-Fi；
- 是否需要外置 AI 协处理器；
- 中国版与全球版是否共用主板。

## 7. 选型闸门

任何平台成为量产候选前，至少通过：

1. 安全内核资源闸门：确定性 Rule Policy / Safety Kernel 的 RAM、Flash、
   延迟和故障恢复；学习模型的精度、INT8、延迟和能耗作为成长评分；
2. 功耗闸门：主控守护、首发音频、4G 数据、GNSS和48—72小时整机测试；
   拍照或先进 AI 只在进入该发布配置时计入硬门，否则保留比较数据；
3. 工程闸门：驱动、调试、OTA、安全启动、生产烧录和故障恢复；
4. 供应闸门：样品、1k/10k/50k报价、MOQ、交期、PCN/EOL和FAE；
5. 合规闸门：中国三网与认证，未来全球区域认证；
6. 成本闸门：完整系统BOM，而不是只比较MCU裸片价格。
