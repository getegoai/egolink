# Safety Companion 数据采集与标注规范 v0.1

> 本规范是工程初始值，必须通过开发板、传感器和 PPK2 实测修订。儿童、老人等敏感人群数据在成人志愿者和模拟场景验证前不得作为第一批采集对象。

## 1. 采集原则

1. 默认只保存结构化特征，不持续上传原始声音或图像。
2. 原始证据仅在事件触发、用户主动请求或 Base 明确请求时采集。
3. 每条数据必须带设备 ID、Unix 时间、单调时间、序号、模式、固件版本和契约版本。
4. 用户确认“安全、需要帮助、误报、取消”是最重要的训练标签。
5. 物理 SOS 不需要模型确认，也不能因网络或模型失败而被丢弃。
6. 每次采集必须记录授权状态和隐私模式。

## 2. 建议采样参数

| 数据 | P0/M1 建议 | 事件窗口 | 说明 |
|---|---:|---:|---|
| 加速度计 | 50 Hz | 事件前 3 s + 后 7 s | 后续比较 25/50/100 Hz 能耗与效果 |
| 陀螺仪 | 50 Hz | 事件前 3 s + 后 7 s | 可在静止状态降采样 |
| 音频 | 16 kHz、16-bit、单声道 | 前 2 s + 后 5 s | 环形缓冲；原始片段默认短时保存 |
| GNSS | 活跃 1 Hz，静止降频 | 事件时立即刷新 | 记录 fix age、精度、速度和方向 |
| 4G/网络 | 30 s 或状态变化 | 事件前后状态 | 信号、注册、延迟、离线时长、流量 |
| 电量/温度 | 30 s | 状态变化 | 后续用于功耗策略与安全保护 |
| 图像 | 按需单帧 | 事件触发后 | 初期 320×240 或 640×480 JPEG，禁止常开 |

## 3. 推荐目录

```text
dataset_root/
├─ manifest.json
├─ sessions/
│  └─ <session_id>/
│     ├─ sensor_frames.jsonl
│     ├─ annotations.jsonl
│     ├─ imu/
│     ├─ audio/
│     ├─ images/
│     └─ device_log.txt
└─ splits/
   ├─ train.txt
   ├─ validation.txt
   └─ test.txt
```

训练、验证、测试必须按人员或完整 session 划分，不能把同一人的相邻窗口随机分散到不同集合中。

## 4. 首批场景

### 负样本

- 正常步行、坐下、躺下、跑步、上下楼；
- 放下设备、拿起设备、背包晃动；
- 正常说话、笑声、电视声、门声；
- 室内 GNSS 漂移、4G 弱信号、短时断网；
- 低电量但仍正常使用。

### 正样本或受控模拟

- 手动 SOS；
- 软垫环境下受控跌倒动作；
- 设备撞击后静止；
- 呼救短语和非语言求救声；
- 走出安全区并停留；
- 长时间异常静止；
- 4G 长时间失联；
- 事件后“安全、需要帮助、无响应”的不同反馈。

禁止通过危险驾驶、真实摔车、真实伤害等方式制造数据。

## 5. 标注

使用 `safety_annotation.schema.json`。至少记录：

- 风险类型；
- 严重程度；
- 用户是否安全、需要帮助或无响应；
- 系统动作结果；
- 标注来源；
- 原始声音和图像是否允许用于训练。

模型教师标签不能替代人工确认。重要测试集必须经过人工复核。

## 6. 隐私和保留

- 设备本地优先；
- 原始音频和图像单独加密并设置短保留期；
- 结构化特征、模型输出和用户确认可保留更久；
- 用户必须可以删除完整 session；
- 隐私模式下不得请求或保存图像、原始音频；
- 上传前移除无关身份信息；
- 云端仅作为明确授权的可选增强，不是基本闭环依赖。

## 7. M1 数据质量门槛

进入首个模型训练前至少满足：

- 时间戳无倒退；
- 事件前后窗口完整率可统计；
- 传感器采样率偏差和缺帧率可统计；
- 每条记录能追溯固件、设备和配置版本；
- 用户确认标签能与事件关联；
- 隐私授权字段完整；
- 原始证据与结构化记录的哈希能够对应。
